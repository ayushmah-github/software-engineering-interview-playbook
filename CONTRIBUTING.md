# Contributing

Contributions are welcome if they make the repository more useful for real interview preparation.

## What we value

- practical questions based on real engineering work
- clear explanations and realistic constraints
- strong rubrics and evaluation guidance
- examples that reflect actual interview trade-offs
- documentation that is easy to follow

## Contribution types

You can contribute by:

- adding interview prompts
- improving rubrics and scoring guidance
- clarifying explanations for backend or system design questions
- documenting study plans or feedback loops
- refining behavioral examples and STAR frameworks

## Contribution guidelines

1. Keep content actionable and realistic.
2. Avoid generic or low-effort scraped question lists.
3. Write prompts with clear constraints, expected trade-offs, and follow-up areas.
4. Prefer quality over quantity.
5. Use concise, readable markdown.
6. Add context when a prompt is ambiguous.

## Pull request expectations

A good PR should include:

- a clear purpose
- relevant examples or scoring notes
- concise explanations
- no marketing language or SEO-driven filler

## Review process

Changes are reviewed for usefulness, clarity, and correctness. The project values resources that candidates can actually use in practice.
